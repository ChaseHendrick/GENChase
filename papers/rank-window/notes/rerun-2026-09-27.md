# Full rerun of the note's programs from the downloaded inputs (2026-09-27)

The rerun that quality item 7 asks for: every program in `code/` run again from the downloaded inputs, from a copy
of this folder, each output compared with the committed one, then `code/make_numbers.py`, `code/make_figures.py` and
the LaTeX build run on the rerun `out/`.

**Result.** Every program ran to completion and every value reproduces. At the README's setting (one BLAS thread)
every output is byte for byte or array for array the committed one, apart from three things: the outputs of
`matern_window.py` (spectra, window exponents, geometry) were committed from a two-thread run and differ from a
one-thread run in the last bits; the Matern rows are written in a different order; and the finite-population file
cannot be regenerated as committed by the README command.
`out/matern_finiteN.json` holds 112 cells, 54 with 20 replicates and 58 with 5, as the Methods describe, but the
committed `matern_finiteN.py` lists only 108 of those cells and the README command `python3 code/matern_finiteN.py 20`
gives every cell 20 replicates. `make_numbers.py` on the rerun `out/` therefore changes 10 macros of
`paper/numbers.tex`, all `\Fin...` (listed below), and five lines of the PDF text. Every stored finite-population value
does reproduce: all 1,370 stored replicate values, 1,290 by the committed program and 80 by a scratch copy that lists
the four missing cells. With the stored cell list and replicate counts, the rerun reproduces `paper/numbers.tex`, the
five tables, `out/tab_grating.tex` and `out/numbers.json` byte for byte, the three figures pixel for pixel and the PDF
text exactly. **Item 7 stays open** until the program and README reproduce `out/matern_finiteN.json` (see "What
differs").

## Setup

- **Code:** commit 67df917. `papers/rank-window/` was exported with `git archive` into a scratch folder outside the
  repository, and its `out/` was emptied except for `LICENSE.md` and regenerated there. The committed `out/` was used
  only for the comparisons. No program was changed. The one scratch-only edit (a diagnostic, not committed) is named
  where it is used.
- **Machine:** cloud container, 4 cores (Intel Xeon @ 2.80 GHz), 15 GB, Linux 6.18, shared with other jobs (load
  average 4 to 11). Python 3.11.15, numpy 2.4.6, scipy 1.17.1 and matplotlib 3.11.2 (the versions in
  `code/requirements.txt`), OpenBLAS 0.3.31 (scipy-openblas64, `DYNAMIC_ARCH`, Haswell kernels), pdfTeX
  3.141592653-2.6-1.40.25 (TeX Live 2023).
- **Settings:** every program ran under `nice -n 19` and a `timeout`, from 03:35 to 08:40 UTC. The first jobs used two
  BLAS threads per process (the machine was shared). After a container restart at about 05:18 UTC every job used one
  thread, the README's setting, and every two-thread output except the Matern spectra and `circle_d1.json` (identical
  already) was made again with one thread. The table gives the thread count of each file in the final rerun `out/`.
- **Inputs** come from the figshare deposit of Stringer et al. (doi:10.25378/janelia.6845348, CC BY-NC 4.0). They were
  kept outside the repository and are not redistributed. The ten stimulus files were downloaded on 2026-09-27 at
  01:21 UTC from `https://ndownloader.figshare.com/files/<file id>`. The calibration recording
  `natimg2800_M170714_MP032_2017-09-14.mat` (file 12462698, 244,220,197 bytes) was downloaded at 03:35 UTC. All
  eleven MD5s equal those in the README table.

**Why the two-thread runs were redone.** The MEME fits are ill-conditioned in the last bits (the full whitening
matrix has condition number 7.7e7). With the two-thread kv parts and data sets (differences of 1e-13 and 4e-16),
`meme_analyze.py` moved alpha2 by up to 5.2e-5; with the two-thread kvN parts as well, by up to 8.7e-4 and a
misfit by 0.11 (in both runs no flag or break changed). `precision_check.py` moved its full-whitening alpha2 by up to
5.5e-7, which changed the printed `\PrecAlphaMax` from 1.2e-7 to 2.9e-7; its first, all two-thread run also moved
`\PrecCvMax` from 3.1e-7 to 1.1e-7 (single-precision cvPCA). Two diagnostics isolate the cause. Run with one thread on the committed inputs, `meme_analyze.py` reproduces the committed
`meme.json` byte for byte (593 s), and `precision_check.py` reproduces the committed `precision.json` (439 s). The
one-thread chain (calibration, `meme_sim.py`, kv, `meme_analyze.py`, `precision_check.py`) then reproduces both files
byte for byte, and `\PrecAlphaMax` with them.

## The first run of `verify_independent.py` (exit code 1)

This was a problem in the scheduling harness, not a disagreement in the results. The scheduling script started
`verify_independent.py` once `matern_window.py` had stopped. But `matern_window.py` had been stopped by its time
limit (exit 124) before it wrote `out/matern_window.json`, so `verify_independent.py` failed at once with
`FileNotFoundError` on that file. Started again after `matern_window.py` finished with exit 0, it passed every check.
Only the scratch scheduling script was at fault.

## What differs, and why item 7 stays open

`out/matern_finiteN.json` is the one committed output that the README commands do not regenerate:

1. **Cell list.** The Methods (and the program's header) describe nu = 1 at every ell >= 1/4 and nu = 0.75 at
   ell = 2, 4, 8 on all ten sets, plus all five nu at ell = 1/4, 1, 4 on 8D MP032 2017-08-10 and 4D MP032 2017-09-22.
   That is 112 cells, the number the committed file holds. The program's `keys_for` adds only nu = 0.5, 1.5 and 2.5
   on those two sets, so it computes 108. The four missing cells are nu = 0.75 at ell = 1/4 and 1 on the two sets,
   with 20 replicates each in the stored file. A scratch copy of the program with nu = 0.75 added to that list (not
   committed) computed the four cells with 20 replicates in 436 s. Their stored entries are reproduced exactly.
2. **Replicate counts.** The stored file has 20 replicates in the 54 cells of the first computation and 5 in the 58
   added in revision, as the note says (`\FinRFirst`, `\FinRAdded`). From an empty `out/`, the README command gives
   every cell 20 replicates, and no README command gives the added cells 5.

Every value is reproducible, but not the file. Closing item 7 needs one of two changes, then a rerun of
`matern_finiteN.py` and `make_numbers.py` from this folder:

- (a) add the four cells to `keys_for` and give the README the two-stage history: a first run with 20 replicates
  restricted to the first computation's cells, then 5 for the rest; or
- (b) regenerate `out/matern_finiteN.json` with one replicate count for every cell (the README command, with the four
  cells added), let `make_numbers.py` rewrite the macros above, reword the Methods sentence on replicate counts, and
  rebuild the PDF.

## Where the rerun is

The rerun copy, its logs (`logs/<job>.time|.log|.err`), the runner and comparison scripts and the downloaded inputs
are in the session scratchpad (`rw-rerun/`), not in the repository: the inputs are CC BY-NC, and the rerun outputs
duplicate the committed ones. The comparison scripts:

- `compare.py`: bytes, then every JSON leaf or array entry.
- `cmp_window.py`: Matern rows keyed by set, nu and ell, and spectra over ranks 1-500.
- `cmp_finiteN.py` and `cmp_finiteN_full.py`: finite-population cells, replicate by replicate.
- `cmp_meme.py`: MEME moments, data set by data set.
- `cmp_stage1.py`: the regenerated inputs.
- `mn.sh`: `make_numbers.py` on a given `out/`, and `cmp` of the eight generated files.
- `figs.sh`: `make_figures.py`, the figures rasterized at 150 dpi and compared pixel by pixel, and the PDF rebuilt
  and its `pdftotext` output compared.
