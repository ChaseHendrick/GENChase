# Rerun of Stage E and Stage S for N = 1 and N = 8 from the copies in code/ (2026-10-01)

Made while drafting this paper, by the drafting agent (not a review). The programs in `code/` were staged with an
empty `results/` (plus `data/cell-gks0.0275.json`, which `existence.py` compares against) in a scratch folder, and run
with python-flint 0.9.0 (FLINT 3.6.0), numpy 2.4.6, scipy 1.17.1, Python 3.11.15, BLAS threads set to 1:

```
python3 fourier/existence.py --N 1,8
python3 fourier/stability.py --N 1,8
```

"90 hashes checked; all match", so the copies in `code/` and `data/` are byte-identical to the files the records hash.

binary values of Y0, Z1, Z2 and r_existence differ slightly (Y0 beyond its 25 printed digits). A plausible cause, not
investigated, is that `existence.py` does not pin BLAS threads, so the untrusted double inverse A_fin may differ in its
last bits between runs; any exact A_fin is admissible, and only the size of the bounds depends on it. The rerun records
are not kept (they are not the records the Stage S hashes refer to). N = 16, 32 and 64 were not rerun.

comparison with `data/` printed "same" for all eight compared keys; exit status 0.
