# Repository automation checks

The timestamp and volunteer-ledger workflows propose generated changes as pull requests. They never merge those proposals. Submitted vortex results are independently re-verified from the base branch, including renamed files; symlink replacements are refused.

Before generation, each workflow captures its reviewed checkout and fetches an existing proposal branch with full history. `tools/automation-branch.js` refuses that branch if its unmerged changes include anything except the workflow's generated outputs: `identities/commitments/*.txt.ots` for timestamps, or `COMPUTE.md` and the two vortex leaderboard outputs for volunteer results. It merges the reviewed base into the existing branch before running the reviewed generators. A merge conflict stops with instructions for manual resolution and leaves the remote head unchanged.

Updates retain the proposal's commits and use a normal push. A concurrent advance is rejected instead of overwritten. A reviewed-base merge is pushed even when regeneration adds no differences; a reused branch whose final tree already matches the base does not open an empty PR. Volunteer push and manual refresh runs share one serialized writer group, while independent submission-PR checks can still run separately. If a push succeeded but PR creation failed, the next run retries opening the existing nonempty proposal without rewriting its commits. An unchanged branch with an already-open PR stays quiet. These workflows never force-push or automatically merge a proposal.

For bot proposals to trigger ordinary `pull_request` checks, configure a separate repository secret named `AUTOMATION_TOKEN`. Use a fine-grained token restricted to **GENChase**, with **Contents: read and write** and **Pull requests: read and write**. The checkout and PR creation use the same token, so updates to an existing proposal also trigger the normal checks. Those events include the usual CodeQL and Pages checks. Keep an appropriate expiry and rotate the secret when needed. No administration permission is required.

Do not repurpose `PAPERS_TOKEN`: it is for the eight companion repositories and their publication workflow. No existing credential is copied or granted additional repository access by this change.

Without `AUTOMATION_TOKEN`, the workflows retain the built-in `GITHUB_TOKEN` path and explicitly dispatch the check and Pages workflows. Those runs validate the candidate branch, but **workflow-dispatch checks do not satisfy required PR check contexts**. The built-in token can also create approval-required `pull_request` runs for `opened`, `synchronize`, and `reopened` events. A user with write access selects **Approve workflows to run** in the pull request to start those runs in the required PR contexts. The separate token lets those PR runs start automatically. The workflow reports the manual-dispatch limitation instead of claiming that its branch-verification runs make the PR ready to merge. See [GitHub's required-check documentation](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks) and [workflow triggering with tokens](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow).

The read-only preprint monitor downloads all eight registered Zenodo source archives and checks titles, Publication / Preprint type, component-rights metadata and the manuscript PDF bytes. It runs weekly and can be dispatched manually. It publishes no records, changes no release assets and never archives GENChase on Zenodo.

`node tools/automation-check.js` exercises the actual shell steps and helper against local Git remotes and a mock GitHub CLI. Its 31 cases include real existing proposal branches, preserved commit ancestry and main updates, unexpected-file, generated-symlink and merge-conflict refusal, concurrent-push rejection, reused merged branches, orphan-branch PR retries and quiet unchanged open PRs, configured-token and built-in-token checks, no-op runs, dispatch failures, renamed submissions and symlink refusal. These fixtures do not verify a live token's permissions.

The [independent regression record](../validation/results/automation-regression-2026-09-29.json) preserves source fingerprints and bounded outcomes. One sandboxed run timed out at 90 seconds; the diagnostic and unchanged-suite retests passed all 31 cases in 44 and 34 seconds within the same cap. The timeout's cause was not established, and no wait budget or criterion was changed.

With the owner's approval, `AUTOMATION_TOKEN` was configured on 2026-09-29. GitHub's form confirmed one selected repository, Contents and Pull requests write access, and required Metadata read access. The encrypted repository-secret listing confirms it was saved; `PAPERS_TOKEN` was not changed. It expires on **2026-10-29** and must be rotated before then. Token creation and storage are distinct from verifying a live automation-created PR's check events.
