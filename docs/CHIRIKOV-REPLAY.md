# Chirikov fixed-work replay, 2026-09-29

The paused standard-map plate now performs exactly the recipe's `iters` kicks for each of its seeded `orbits`. The count includes burn-in; an orbit contributes a histogram hit only after `burn` kicks. Thus a freshly generated, undisturbed plate reports `orbits * iters` total kicks and `orbits * max(0, iters - burn)` hits. The initial budget is the same with reduced motion enabled. The exact counters appear in the status line.

Turn Accumulate off (`running: false`) to reproduce the fixed initial plate. Enabling Accumulate continues in time-bounded batches beyond it. A running recipe does not save the elapsed trajectory or later pointer disturbances. Global pause can hold the current picture, but a saved recipe is not a checkpoint of that accumulated state.

Previously regeneration ran for 40 milliseconds, or 80 milliseconds with reduced motion, and ignored `iters`. Its work count depended on browser speed and scheduling, even for `running: false`. Those historical pixels cannot be reconstructed uniquely from the recipe. This correction therefore changes their initialization rather than claiming pixel identity with an unknowable prior stopping point. The recipe schema and global version remain unchanged; existing keys retain their intended meanings.

The map, tangent update, seeded initial conditions, 24-kick walker batching, burn comparison, histogram precision and coloring are retained. Only the final batch is shortened to respect the exact iteration budget. Fractional iteration and burn counts are rounded to integers; malformed orbit counts fall back to 2400. The kick sanitizer now preserves the valid value `K = 0`, previously replaced by the default through a false-value fallback. Its existing upper bound is retained.

`node tools/chirikov-replay-check.js` loads the maintained module with drawing omitted and rejects any wall-clock access during paused initialization. An independent transcription compares every walker field and all three Float32 histograms for five finite recipes, including zero kick, a partial 24-step batch, portrait geometry, and a burn period covering all initial work. The integrable `K = 0` case also checks constant momentum and the closed-form linear angle against a 1e-11 tolerance, with zero tangent growth. Controls change the seed, work count and kick sign. These checks concern finite implementation behavior, not the last KAM threshold or asymptotic Lyapunov exponents.

`node tools/chirikov-print-state.js` exercises actual paused hash loads, changed-seed/work controls, the real iteration control, reduced motion and the shell PNG export. It requires exact replay of preview pixels, counters and accumulated fields, and unchanged walker/histogram state across export. The print remains a tone-mapped density raster with a 720-pixel longest accumulation-grid edge. One Chromium run does not establish color calibration or cross-platform pixel identity.

Recorded results are `validation/results/chirikov-replay-check.json` and `validation/results/chirikov-print-state.json`. The technique remains unvalidated outside these bounded replay and state-preservation checks.
